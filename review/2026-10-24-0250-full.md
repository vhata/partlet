## Invariants

These are expected contracts; the findings identify observed violations.

- Exports contain only declared current and previous paths, including
  historical content; symlink targets are displayed without being read.
- The same source history, path list, mailmap and tool versions produce
  stable export commits; appending project history preserves old hashes.
- Export destinations are fresh bare repositories outside the supplied
  source checkout and its Git directories, with inherited Git selectors
  removed.
- First publication requires approved ancestry; subsequent publication
  fast-forwards unless the exact published tip authorizes a rewrite.
- Every advertised ref must be obtainable from advertised packs at each
  observable pointer-write boundary, including interrupted rewrites.
- Cleanup preserves live data and the previous generation's grace period
  while eventually removing abandoned uploads.
- Site object names preserve distinct Git paths. The local store must be
  able to represent every generated key without file/directory clashes.
- Repository text cannot introduce executable HTML through rendered
  Markdown, highlighted source, filenames or symlink descriptions.
- One project's failure does not stop other projects; the index reflects
  published `current` records, including projects no longer in a manifest.
- Test collection and execution should both be isolated from real Git
  discovery and user configuration; an all-skipped suite fails the gate.

## Findings

### Open and Moved

- `rewrite-pack-list-before-refs` — **An interrupted allowed rewrite makes
  the published repository unclonable.** Bug · Open · Verified.
  - Where: `src/partlet/gitstatic.py:80` (`write_pointers`), with full-pack
    replacement at `src/partlet/gitstatic.py:74`.
  - Severity: P1.
  - Publish an approved history, amend it, approve the new export and
    authorize rewriting the old tip. Inject a store failure immediately
    before writing `git/info/refs`: the pack list names only the new full
    pack while refs retain the old tip. A real localhost HTTP clone exits
    128 with `Unable to find` the old tip, although the old pack remains
    stored; retrying restores cloning. Advertise both generations while
    moving refs, then retire the old list safely.
  - Existing task: `publish-orphan-sweep` in `TODO.md`; open PR #3
    explicitly includes this ordering repair, outside this review.

- `interrupted-publish-orphan-keys` — **Interrupted publishes leave keys
  that later successful publishes never remove.** Bug · Open · Verified.
  - Where: `src/partlet/publish.py:103` (`publish_project` unchanged return),
    `src/partlet/publish.py:147` (superseded-key recording), and
    `src/partlet/publish.py:58` (`_run_cleanup`).
  - Severity: P2.
  - Cleanup depends on a final `cleanup.json` write, so interruptions can
    leave keys unnamed by either live pointers or cleanup. In the rewrite
    reproduction above, retry and a further successful fast-forward leave
    the original pack stored, unadvertised and absent from cleanup.
    Reconcile stored keys against live and grace generations, including
    unchanged runs, as the existing task requires.
  - Existing task: `publish-orphan-sweep` in `TODO.md`; open PR #3 covers
    this known defect. Its implementation was not reviewed here.

- `site-directory-index-key-collision` — **A directory named `index.html`
  can make a local build fail.** Bug · Open · Verified.
  - Where: `src/partlet/site/render.py:107` (`render_project`).
  - Severity: P2.
  - A project containing `docs/index.html/leaf.txt` produces both
    `tree/docs/index.html` and `tree/docs/index.html/index.html`. The first
    key is a file ancestor of the second, which a filesystem-backed store
    cannot represent. A real export and `publish_all` return project
    status `failed` with `IsADirectoryError`; other projects continue.
    Choose an unambiguous directory-page key representation and carry it
    through the planned Worker lookup.
  - Review backlog: `site-directory-key-layout`.

- `site-lossy-git-filename-decoding` — **Distinct Git filenames silently
  overwrite each other's site content.** Bug · Open · Verified.
  - Where: `src/partlet/site/tree.py:44` (`read_tree`), with overwrites in
    `src/partlet/site/render.py:128` (`render_project`).
  - Severity: P2.
  - Build a Git tree with byte filenames `file-\xfe.txt` and
    `file-\xff.txt` containing different data. UTF-8 replacement decoding
    maps both to `file-\ufffd.txt`; rendering silently retains only the
    second raw/blob output. Preserve a reversible path identity through
    storage and URL generation, or fail explicitly before publication
    when a path cannot be represented. Git packs and archives are not
    shown to lose these files by this reproduction.
  - Review backlog: `site-git-path-identity`.

- `collection-before-git-sandbox` — **Test module collection runs before
  Git discovery and user configuration are isolated.** Test · Open · Read.
  - Where: `tests/conftest.py:94` (`_git_sandbox`), with import-time
    environment stripping at `tests/conftest.py:32`.
  - Severity: P2.
  - The session fixture changes cwd, HOME, configuration and discovery
    ceilings only after pytest imports test modules. A synthetic checkout
    using exact copies of the current conftest and helpers demonstrated
    that module-level `git rev-parse --show-toplevel` still discovers the
    enclosing checkout and HOME remains the original synthetic HOME;
    both change once the fixture starts. A module-level mutating command
    could therefore reach real state; that damage is an inspection-based
    risk, not a destructive reproduction. Establish isolation before
    collection, after capturing and arming the tripwire; detection after
    mutation does not provide containment or cover worktree/index data.
  - Review backlog: `test-collection-git-isolation`.

- `export-branch-tag-shadow` — **A same-named tag can make an existing
  project directory appear missing on the publishing branch.** Bug · Open · Verified.
  - Where: `src/partlet/export.py:74` (`_require_directory`).
  - Severity: P2.
  - Create tag `main` before adding `foo/` to branch `main`, then export
    that project. The branch existence check uses `refs/heads/main`, but
    the directory lookup uses ambiguous `main:foo` and resolves the tag;
    export reports that the directory moved although
    `git cat-file -t refs/heads/main:foo` returns `tree`. Use the fully
    qualified publishing branch consistently for preflight lookups.
  - Review backlog: `export-qualified-branch`.

- `export-colon-path-rename` — **A valid colon-containing directory passes
  manifest validation but cannot be exported.** Bug · Open · Verified.
  - Where: `src/partlet/export.py:59` (`export_project`), and
    `src/partlet/manifest.py:71` (`normalize_path`).
  - Severity: P3.
  - Exporting a real `foo:bar/a.txt` project fails because the generated
    `--path-rename foo:bar/:` argument contains more than one colon.
    filter-repo rejects it with `--path-rename expects one colon`.
    Either support these names through a different rename mechanism or
    validate the restriction with an actionable manifest error.

- `site-readme-heading-anchors` — **README table-of-contents links lack
  generated heading targets.** Design · Open · Verified.
  - Where: `src/partlet/site/markdown.py:13` (`_parser`).
  - Severity: P3.
  - Render an Install link to `#installation`, followed by `## Installation`:
    the link remains but the emitted heading has no `id` or named anchor.
    A heading-ID policy would make common README tables of contents work.
    The current design does not explicitly promise generated anchors.

- `all-skipped-test-gate` — **A suite containing only skipped tests passes
  the test gate.** Tooling · Open · Verified.
  - Where: `scripts/test.sh:10`; policy at `docs/QUALITY.md:37`.
  - Severity: P3.
  - Run the test script against a single synthetic marked-skipped test:
    pytest prints `1 skipped` and exits zero, which the script forwards.
    That contradicts the documented empty-or-skipped-suite failure rule.
    Require at least one executed test while retaining legitimate
    platform-specific skips in an otherwise executed suite.
