## Invariants

- Export only declared current and previous project paths, including
  historical content; preserve source repositories and configuration.
- Repeated exports with the same history, paths, mailmap and toolchain
  retain commit identities. Appended history preserves published
  ancestry. Cross-version Git determinism has not been established.
- Export destinations are fresh independent bare repositories outside
  the source checkout and Git directories. Inherited Git selectors do
  not redirect child commands; same-named tags do not shadow branches.
- Publication uses the configured branch tip and committed manifest.
  Approval and the exact rewrite authorization guard history changes.
- Every R2 project upload scans the complete reachable export history,
  including merge resolutions and deleted side-branch content. Accepted
  findings use explicit scanner configuration or native fingerprints.
- Only the publishing step receives R2 write credentials. Child tools do
  not inherit its access keys. The Action loads code and dependencies
  from its selected checkout rather than the private source checkout.
- Source publication, removal and recovery are serialized. Locks fail
  closed without automatic expiry; uncertain deletes are never retried.
- Refs never advertise objects unavailable through the pack list.
  Required static metadata is restored before recovery reports success.
- Superseded packs retain live/previous references plus durable timed
  retirement grace; revival clears timers before advertisement. Cleanup
  also runs on unchanged publications and retires orphan uploads.
- Every legitimate local key is listable; actual active temporary files
  remain distinct from committed names. Unsupported filesystem path
  identities fail before publication writes or the unchanged shortcut.
- Public routes reach only intended project objects, not locks, internal
  pointers, arbitrary keys or private repository data. The Worker has no
  write path or publisher credential.
- Mutable Git metadata uses `no-store`; only content-addressed packs and
  indexes are immutable. Validators, ranges and stable-site caching obey
  the documented retention and client-fetch limits.
- Rendered content cannot introduce executable repository HTML. Raw
  responses enforce content policy independently of stored metadata,
  with sandboxing and `nosniff`; symlinks are displayed, never followed.
- One project's failure does not stop unrelated projects. The index
  reflects published records, including entries removed from the
  manifest.
- Test collection and execution preserve real repositories, user Git
  configuration and credentials. A wholly skipped suite must fail.

## Findings

### Open and Moved

- `publish-retry-missing-head` — **An interrupted first publication
  reports successful recovery without restoring Git HEAD.** Bug · Open ·
  Verified.

  - Where: `src/partlet/publish.py:206` (`publish_project` pack-plan
    guard), `src/partlet/publish.py:224` (conditional pointer writes),
    and `src/partlet/gitstatic.py:90` (`write_pointers`).
  - Severity: P3.
  - Fail a LocalStore `put` for `s/p/foo/git/HEAD` after the initial
    pack list and refs have been written, then retry the same approved
    export with a normal store. Retry reports `published` and writes
    `current`; another run reports `unchanged`, but HEAD remains absent
    because equal refs suppress the pack/pointer path. A later tip
    advance restores it; plain HTTP clone succeeds by inferring the sole
    branch, so no clone failure or release blocker is claimed. Repair
    missing required static metadata during retry before reporting
    success.
  - Review backlog: `publish-retry-static-head`.

- `export-colon-path-rename` — **A colon-containing source directory
  passes validation but cannot be exported.** Bug · Open · Verified.

  - Where: `src/partlet/export.py:59` (`export_project`) and
    `src/partlet/manifest.py:127` (`normalize_path`).
  - Severity: P3.
  - A real project at `foo:bar/a.txt` passes path normalization but
    generates `--path-rename foo:bar/:`; filter-repo fails with
    `--path-rename expects one colon`. The original reproduction still
    fails. Support the path or reject it with an actionable manifest
    diagnostic before creating an export.
  - Review backlog: `export-colon-path-validation`.

- `all-skipped-test-gate` — **An entirely skipped Python suite passes
  the test gate.** Tooling · Open · Verified.

  - Where: `scripts/test.sh:10`; policy at `docs/QUALITY.md:63`.
  - Severity: P3.
  - Run `bash scripts/test.sh -o addopts= <scratch-test.py>` with one
    `pytest.mark.skip` test and no executed cases: the command reports
    one skipped and exits zero. Enforce at least one executed test while
    permitting individual platform skips. Empty collection already
    fails. This does not invalidate the ordinary baseline, which
    executes hundreds of tests, or the separately executed end-to-end
    marker.
  - Review backlog: `require-executed-python-tests`.

- `site-readme-heading-anchors` — **README fragment links lack generated
  heading targets.** Design · Open · Verified.

  - Where: `src/partlet/site/markdown.py:13` (`_parser`).
  - Severity: P3.
  - Render an Install link to `#installation` followed by the matching
    heading: the link retains its fragment but the heading has no ID or
    named anchor. The original reproduction still fails. A heading-ID
    policy would support common README navigation; generated anchors are
    not an explicit requirement of the current first-version contract.
