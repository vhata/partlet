## Summary

The baseline and synthetic local build, clone and incremental pull pass.
Six historical findings are confirmed fixed, including the interrupted
rewrite and orphan-sweep defects. Five findings remain open: one P2 and
four P3. Two are new LocalStore defects: filesystem identity can merge
distinct valid Git paths, and temporary-file filtering hides legitimate
published keys from cleanup.

This is a full review of the maintained publisher core and local site
builder, rather than an implementation review of future plans. Worker,
R2 publishing, secret scanning, the action and review CLI remain planned
work. No product fixes are included in the review PR.

## Invariants

These are expected contracts; findings identify observed violations.

- Exports contain only declared current and previous paths, including
  historical content; symlink targets are displayed without being read.
- Identical source history, paths, mailmap and tool versions produce
  identical export commits; appending history preserves earlier hashes.
- Export destinations are fresh bare repositories outside the supplied
  checkout and Git directories, with inherited Git selectors removed.
- Publishing-branch preflight and export resolve the same branch even
  when a tag has the same name.
- First publication requires approved ancestry; later publication
  fast-forwards unless the exact published tip authorizes a rewrite.
- At every pointer-write boundary, advertised refs remain obtainable
  through the advertised pack list, including interrupted rewrites.
- Cleanup preserves live and previous generations, runs on unchanged
  builds, and eventually removes abandoned and retired uploads.
- Every legitimate stored key is visible to listing and cleanup;
  temporary implementation files occupy a distinct namespace.
- Distinct supported Git paths remain distinct through rendering,
  storage and URL generation, including filesystem identity rules.
  Unrepresentable paths fail before publication changes live pointers.
- Repository text cannot introduce executable HTML through Markdown,
  source highlighting, filenames, descriptions or symlink displays.
- One project's failure does not stop others; the site index reflects
  published current records, including removed manifest entries.
- Test collection and execution are isolated from real Git discovery
  and user configuration; an entirely skipped suite fails the gate.

## Findings

### Open and Moved

- `local-store-filesystem-path-alias` — **Distinct valid Git paths silently
  overwrite each other's local site content.** Bug · Open · Verified.
  - Where: `src/partlet/store.py:38` (`LocalStore._path`) and
    `src/partlet/store.py:56` (`LocalStore.put`).
  - Severity: P2.
  - Commit distinct `foo/A.txt` and `foo/a.txt` with different bytes via
    the Git index, export, approve and publish into LocalStore on this
    Mac's case-insensitive filesystem. Publication reports success, but
    both raw keys return the latter file's bytes while the export retains
    both originals; distinct composed/decomposed Unicode names also
    alias, confirmed against byte-safe `read_tree` entries. Preserve
    distinct key identities in the local backend or reject collisions
    before uploads; valid UTF-8 alone does not establish representability.
  - Review backlog: `local-store-path-identity`.

- `local-store-temp-prefix-hides-content` — **Legitimate temporary-looking
  filenames escape listing and retirement cleanup.** Bug · Open · Verified.
  - Where: `src/partlet/store.py:70` (`LocalStore.list`), consumed by
    `src/partlet/publish.py:84` (`_sweep`).
  - Severity: P3.
  - Publish a project containing `.partlet-tmp-keep`, then advance its
    history and publish twice so the first build leaves its grace period.
    Its raw and blob objects remain physically stored because listing
    excludes every basename beginning with `.partlet-tmp-`; direct reads
    succeed even while listing reports neither key. Distinguish actual
    temporary files from valid committed keys instead of reserving an
    undeclared source-filename prefix.
  - Review backlog: `local-store-list-committed-temp-names`.

- `export-colon-path-rename` — **A colon-containing source directory passes
  validation but cannot be exported.** Bug · Open · Verified.
  - Where: `src/partlet/export.py:59` (`export_project`) and
    `src/partlet/manifest.py:71` (`normalize_path`).
  - Severity: P3.
  - Exporting a real `foo:bar/a.txt` project still fails because generated
    `--path-rename foo:bar/:` contains more than one colon; filter-repo
    reports `--path-rename expects one colon`. Support such paths through
    another rename mechanism or reject them with a manifest diagnostic.

- `site-readme-heading-anchors` — **README table-of-contents links still
  lack generated heading targets.** Design · Open · Verified.
  - Where: `src/partlet/site/markdown.py:13` (`_parser`).
  - Severity: P3.
  - An Install link to `#installation` followed by `## Installation`
    retains its fragment link but emits a heading without an ID or named
    anchor. A heading-ID policy would support common README tables of
    contents; generated anchors are not an explicit current requirement.

- `all-skipped-test-gate` — **An entirely skipped suite passes the test
  gate.** Tooling · Open · Verified.
  - Where: `scripts/test.sh:10`; policy at `docs/QUALITY.md:37`.
  - Severity: P3.
  - Run the exact script with a synthetic file containing only one
    `pytest.mark.skip` test: it prints `1 skipped` and exits zero. Require
    at least one executed test while allowing legitimate individual skips;
    an empty collection already fails with pytest exit five.

### Closed

Each closure below was checked against current source and an executed
reproduction or equivalent regression scenario, rather than PR titles.

- `rewrite-pack-list-before-refs` — Fixed in #3 (`fd19ab2`). `src/partlet/gitstatic.py:88` (`write_pointers`): advertises dropped and new packs together until refs move. Interrupted rewrite before refs and before the final pack list remains HTTP-clonable; abandon/retry scenarios pass.
- `interrupted-publish-orphan-keys` — Fixed in #3 (`fd19ab2`). `src/partlet/publish.py:64` (`_sweep`), called at lines 119 and 167: lists stored content against live/grace pointers, including unchanged runs. Interrupted uploads and superseded generations are removed in regression scenarios. The separately recorded temporary-prefix omission is a narrower listing defect.
- `site-directory-index-key-collision` — Fixed in #11 (`c03abbc`). `src/partlet/site/render.py:110` (`render_project`): descendant directory keys use a separate `children/` namespace. Original `docs/index.html/leaf.txt` and stronger nested cases persist and read back through LocalStore.
- `site-lossy-git-filename-decoding` — Fixed in #10 (`e6a9bb7`). `src/partlet/site/tree.py:48` (`read_tree`): strict decoding rejects invalid UTF-8. Original distinct byte-name reproduction now raises an actionable TreeError; publication regressions confirm rejection before pointer changes and on unchanged builds.
- `collection-before-git-sandbox` — Fixed in #9 (`82afab6`). `tests/conftest.py:58` (`pytest_sessionstart`): arms the tripwire and enters the sandbox before collection. Five independent collection/lifecycle scenarios pass, including collect-only, collection errors and synthetic-config mutation detection.
- `export-branch-tag-shadow` — Fixed in #8 (`caedd96`). `src/partlet/export.py:74` (`_require_directory`): uses `refs/heads/<branch>:<path>`. Same-named tag scenarios now export branch content, reject absent/file paths on that branch, and reject a tag without a corresponding branch.
